## 1. What was built

### 1.1 An AVX-512 kernel tier

`BlockConfig::avx512` (default on) selects a third kernel set above AVX2+FMA when the CPU has
AVX-512 F/DQ/VL/BW (`blocked::avx512_available()`, checked once; the environment variable
`QSIM_NO_AVX512` forces it off, mirroring `QSIM_NO_AVX2` in `src/shor/sliced.rs`). Code:
`src/engines/blocked/avx512.rs`, written with explicit `core::arch::x86_64::_mm512_*`
intrinsics behind one small trait (`Simd`, implemented for `f32` x 16 lanes and `f64` x 8 lanes),
so each kernel is written once for both precisions.

Why explicit kernels: the executor's generic kernels are straight loops over contiguous runs,
which LLVM vectorises well when runs are long. With 16 `f32` lanes per register every target or
control below bit 4 (bit 3 for `f64`) sits *inside* a vector: the generic code then walks runs of
1-8 elements, a gather/scatter of groups of 8 (`u1_group8`), or plain scalar loops
(`small_pairs`, and the diagonal kernel when a pivot condition is on bit 0 or 1). On main the
profile of brickwork-24 put 22% of the time in those "small-bit" paths.

| kernel | how it works |
|---|---|
| 1-qubit gate, target inside the vector | new = `A x + B perm(x)` with per-lane coefficient vectors (`m00`/`m01` where the target bit is 0, `m11`/`m10` where it is 1); one `vpermps` per register; X gates are lane blends |
| 1-qubit gate, target above the vector | vertical pairs of registers, broadcast coefficients |
| controls inside the vector | folded into the coefficient vectors (`A = 1`, `B = 0` on lanes whose controls are not all set): no masking at run time |
| controls above the vector | select which registers are visited (`for_each_run` over register indices) |
| pair (two 1-qubit gates + optional CNOT, one sweep) | each gate inside or across registers; the CNOT is a blend or a lane permutation; pairs may now also form on bits 0 and 1 |
| dense 2^k x 2^k block (k = 2, 3) | tiles of 2^k registers; every in-vector target is first exchanged with a free register bit by two-source permutes (`vpermt2ps`, an involution), so the product is vertical with broadcast matrix entries |
| diagonal block, single pass (new) | see 1.2 |
| AoS <-> SoA block load/store | two registers per step, `vpermt2ps` deinterleave / interleave |

Everything else (swaps, single-group diagonal blocks, blocks smaller than one register) runs the
generic kernels compiled inside the AVX-512 functions. Each op kind is its own non-inlined
`#[target_feature(enable = "avx512f,avx512dq,avx512vl,avx512bw,avx2,fma")]` function,
instantiated for `f32` and `f64` in the library only (a first version with one generic,
fully inlined stage loop multiplied the library's release compile time by ~3 and every
downstream crate's by more, because generic code is re-instantiated per crate).

### 1.2 Single-pass diagonal blocks

The executor applies a run of diagonal terms (CZ, controlled phases, the QAOA `ZZ` terms, the
QFT's phases) as a "diagonal block": terms on two or more buffer bits are grouped by a common
pivot bit, and each group is one pass over the block. A layer of CZs on disjoint pairs has no
common pivot, so it costs one pass per pair; a QAOA layer on a 3-regular graph about one per
three edges. On main the profile put 28% of brick_cz-24 and 41% of QAOA-24 in diagonal passes.

In the AVX-512 tier, a block with two or more groups is rewritten (`diag_pass`, at preparation)
into one pass: buffer index = row `h` (bits >= 8) and low part `x` (bits < 8); the factor is
`lo[x] * hi[h] * prod(crossing terms)`, where `lo` (256 entries) holds every term inside the low
8 bits, `hi` every term inside the row bits, and a term crossing the split on one low bit `a`
becomes a per-row factor on bit `a`. Per row, the crossing factors on lane bits form one
coefficient register and those on the register-index bits a scalar per register, so the inner
loop is two complex multiplies per register, the same as one pivot-group pass. Terms with an
outer-qubit condition are folded in per chunk. Blocks with a term crossing the split on two or
more low bits (multi-controlled phases) keep the pivot form. The rewrite happens only in the
AVX-512 tier's preparation, not in `prepare_mapped`, so the graph compiler's in-place patching
of phases (`OpLoc`) is unaffected.
